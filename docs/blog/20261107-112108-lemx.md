## 调试前的环境隔离与数据脱敏

Chrome DevTools 的性能面板能记录完整的网络请求、JS 执行栈与内存快照，这些数据往往包含 Session ID、CSRF 令牌、用户标识等敏感信息。安全规范的第一条是：性能剖析只在隔离的测试环境或脱敏后的数据副本上进行。若必须复现生产问题，应在 Network 面板中启用「保留日志」的同时，通过本地覆盖（Local Overrides）替换响应体中的敏感字段，或使用 DevTools 的请求阻断功能过滤含凭证的接口。录制 Performance 面板时，避免勾选「内存」选项，因为堆快照可能捕获表单明文与令牌字符串。

## 网络请求审查与凭据保护

在 Network 面板中调试 API 时，务必关闭「保留日志」以外的持久化选项，防止刷新后请求头中的 Authorization 与 Cookie 被写入磁盘缓存。审查 JSON API 响应时，利用「响应」标签的格式化视图而非直接复制原始内容到外部工具，减少凭证外泄风险。对于跨域调试，不应为了图方便临时禁用 CORS 或关闭 HTTPS 证书校验；正确做法是在本地启动反向代理并配置自签名证书，同时保持 HSTS 策略在测试环境中的一致性，避免调试配置被误带入生产。

## 性能脚本注入的边界约束

使用 Snippets 与 Console 执行性能测量脚本时，需遵循最小权限原则。禁止在页面上下文直接注入会读取 document.cookie 或 localStorage 的代码；若需测量首屏渲染时间，优先使用 PerformanceObserver 监听 paint 与 largest-contentful-paint 条目，而非遍历 DOM 提取业务数据。对于长期运行的性能监控脚本，应通过 DevTools 的「工作区」映射到本地源码文件，并在提交前移除所有调试断点与 console 输出，防止源码映射泄露内部路径结构。

## 生产环境调试的合规红线

线上环境开启 DevTools 远程调试端口（如 --remote-debugging-port）等同于开放任意代码执行入口，必须严格禁止。若需在生产环境做性能采样，应通过服务端埋点与 Real User Monitoring 收集数据，而非在客户端挂载调试钩子。调试结束后，及时清除 Application 面板中的 Service Worker 缓存与 IndexedDB 记录，避免残留的预取数据在离线场景下被未授权读取。遵循这些规范，性能调试才能在不削弱站点安全基线的条件下进行。

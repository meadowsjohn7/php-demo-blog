## 调度层：用户如何被导向最近的边缘节点

CDN 加速的第一步不是缓存，而是调度。用户发起请求时，权威 DNS 会依据解析来源的地理位置、运营商线路以及节点实时健康度，返回一个就近边缘节点的 IP。这一步通常结合 Anycast 与 GeoDNS 完成：Anycast 让同一 IP 在多个机房宣告，由网络路由自然收敛到最近入口；GeoDNS 则用于更细粒度的区域分流。对 PHP Demo Blog 这类轻量项目而言，需要在源站配置中保留真实客户端 IP 的透传头，否则后续的限流、日志与 Session 绑定都会失真。调度质量直接决定首字节响应时间，节点选错，后面的缓存与压缩再优也补不回来。

## 缓存层：边缘命中率决定回源成本

边缘节点收到请求后，先查本地缓存。静态资源通过 Cache-Control、ETag 与 Vary 头控制新鲜度，动态 JSON API 则适合用短 TTL 加 stale-while-revalidate，让节点在后台回源刷新时仍能返回旧副本。提升命中率的关键是缓存键设计：把与内容无关的查询参数剔除，把 Accept-Encoding 纳入 Vary，避免 Brotli 与 gzip 副本互相污染。对图片做无损压缩并配合 Lazy-loading，能进一步压低边缘存储与回源带宽。回源侧建议使用原生查询配合合理索引，避开 ORM 序列化开销，让源站在缓存未命中时也能快速响应。

## 协议层：HTTP/3 与 TLS 1.3 的协同收益

边缘到用户这一段是 CDN 最能发挥协议优势的地方。启用 HTTP/3 基于 QUIC，在弱网与移动场景下减少队头阻塞，配合 Brotli 压缩文本资源，可显著降低 TTFB。TLS 1.3 将握手压缩到一次往返，并配合 HSTS 策略强制加密，既提升安全性，也符合搜索引擎对安全站点的偏好。需要注意的是，HTTP/3 依赖 UDP 与 Alt-Svc 宣告，边缘节点必须正确下发该头，否则浏览器不会升级。对 API 响应启用 Early Hints 预加载关键资源，也能让 LCP 指标更稳定。

## 安全与一致性：加速不能牺牲正确性

CDN 放大流量的同时也会放大攻击面。在 Web 层实施严格的 CSRF 令牌验证与 XSS 过滤，是边缘缓存之外必须保留的源站防线。负载均衡环境下，Session 状态建议放入分布式 Redis 集群，保证用户在多节点间切换时状态一致；否则边缘调度越分散，登录态丢失越频繁。对过期 URL 用 301 做权重迁移，并在边缘层用 Lua 实现动态 IP 黑名单，可过滤非法爬虫、降低源站 CPU 负载。把这些环节串成闭环，CDN 才不只是“快”，而是可运维、可审计的加速基础设施。

自动化测试 Selenium 脚本：完整手册

2026-11-04 · PHP Demo Blog #Selenium #自动化测试 #PHP #WebDriver #CI/CD
本手册系统讲解 Selenium 自动化测试脚本的编写要点，涵盖环境配置、元素定位、等待策略、Page Object 模式及 CI 集成，帮助团队构建稳定可维护的测试套件。

环境准备与基础配置

编写 Selenium 脚本的第一步是搭建可复现的测试环境。推荐使用 Selenium WebDriver 4.x 配合 PHP 的 php-webdriver 库，通过 Composer 安装 `php-webdriver/webdriver`。浏览器驱动建议使用 WebDriverManager 自动管理，避免手动下载 chromedriver 的版本错配问题。在 PHP Demo Blog 项目中，我们通常将测试脚本放在 `tests/Selenium` 目录下，并通过环境变量注入基础 URL 和浏览器类型，便于本地与 CI 环境切换。

启动会话时，应显式设置超时时间和无头模式参数。例如，在 ChromeOptions 中启用 `--headless=new`、`--no-sandbox` 和 `--disable-dev-shm-usage`，以适配容器化运行环境。同时，为每个测试用例生成独立的会话，避免状态污染。

元素定位与等待策略

稳定的元素定位是脚本可靠性的核心。优先使用 `data-testid` 属性而非易变的 CSS 类名，并在页面开发阶段与前端约定测试标识。对于动态加载的 JSON API 驱动页面，应使用显式等待（Explicit Wait）而非固定睡眠。php-webdriver 提供了 `WebDriverWait` 类，可结合 `ExpectedConditions` 等待元素可见或可点击。

例如，等待博客列表加载完成时，可等待 `presenceOfElementLocated` 条件，超时设为 10 秒。避免使用 `sleep()` 硬等待，它会拖慢整体测试时长并引入不稳定性。对于异步请求较多的场景，可结合浏览器日志或网络拦截能力，但需注意跨浏览器兼容性。

Page Object 模式与可维护性

随着用例增长，脚本会迅速变得难以维护。采用 Page Object 模式将页面元素和操作封装为类，每个页面类只暴露业务方法。例如，为博客首页创建 `HomePage` 类，包含 `open()`、`getPostTitles()` 和 `clickFirstPost()` 方法。测试用例只调用这些方法，不直接操作定位器。这样当页面结构变更时，只需修改 Page Object，而不必改动所有用例。

此外，将公共断言和辅助函数抽取到基类中，如 `assertElementVisible()` 和 `waitForUrlContains()`。结合 PHPUnit 的数据提供器，可以对同一流程使用多组输入进行参数化测试，提高覆盖率。

集成到 CI 与结果分析

将 Selenium 脚本集成到持续集成流水线时，建议使用 Docker 启动 Selenium Grid 或独立浏览器容器，确保环境一致性。在 GitLab CI 或 GitHub Actions 中，通过服务容器启动 selenium/standalone-chrome 镜像，并设置 `SELENIUM_HOST` 环境变量指向该服务。测试执行后，收集截图和浏览器日志作为失败证据，便于快速定位问题。

对于失败用例，应自动重试一次以排除偶发网络抖动，但需记录重试次数。最终生成 JUnit XML 报告，并上传为流水线产物。通过定期清理测试数据和隔离测试环境，可以保持脚本长期稳定运行，为项目质量提供持续保障。

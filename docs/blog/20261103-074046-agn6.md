## 词法分析与标记流压缩

代码压缩的第一步是词法分析。PHP 的 token_get_all() 将源码拆分为标记流，压缩器据此安全地移除注释、空白和冗余标记。关键在于区分字符串字面量与代码结构：单引号字符串内的空格必须保留，而运算符两侧的空白可安全删除。一个常见的实现是遍历标记流，跳过 T_COMMENT 与 T_DOC_COMMENT，合并连续空白为单个空格，并在不改变语义的前提下删除换行。这种标记级压缩对 PHP 尤其有效，因为 PHP 对空白不敏感，但需注意 heredoc/nowdoc 结构内的内容不可触碰。压缩后体积通常减少 20% 到 40%，且不引入运行时开销。

## 标识符重命名与作用域分析

混淆的核心是标识符重命名。底层依赖抽象语法树（AST）进行作用域分析：PHP-Parser 将代码解析为 AST 后，遍历变量、函数与类节点，建立符号表。局部变量可安全重命名为短标识符（如 $a、$b），但全局变量、超全局变量、魔术方法及动态调用的函数名必须保留。重命名时需处理变量变量（$$var）和 eval 等动态特性，保守策略是遇到动态构造即跳过该作用域。字符串中的函数名若被 call_user_func 动态调用，也需通过静态分析识别并保护。这一阶段决定了混淆的强度与安全边界。

## 字符串编码与控制流变换

字符串常量是信息泄露的主要来源。底层策略包括十六进制转义（\x41）、Base64 编码后运行时解码，或拆分为字符数组拼接。更高级的变换是控制流扁平化：将顺序执行的语句块转换为 switch 分发循环，用状态变量驱动执行顺序。这增加了逆向阅读成本，但会引入运行时开销，通常用于授权校验等敏感逻辑而非性能关键路径。另一种常见手法是插入不透明谓词（如 if (1 === 1)），配合死代码消除，使静态分析难以简化。所有变换必须保证异常处理与 finally 块的语义不变。

## 性能权衡与工程实践

压缩与混淆并非免费。控制流扁平化可能使 opcache 的优化效果下降，字符串解码增加 CPU 开销。工程上建议分层处理：发布包使用标记级压缩与局部变量重命名，敏感模块再叠加字符串编码。压缩产物应保留 source map 或未混淆副本用于调试。对于 PHP Demo Blog 这类项目，可在构建脚本中集成 PHP-Parser 实现自动化，但需在 CI 中运行完整测试套件，验证压缩前后行为一致。最终目标是体积与可读性的平衡，而非追求极端混淆。

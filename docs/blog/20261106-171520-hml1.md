## 输入验证与资源限制

在接收用户上传的图片并转换为 WebP 时，首要任务是严格验证输入。使用 `finfo_file()` 或 `getimagesize()` 检查文件类型，确保仅允许 JPEG、PNG 等预期格式，避免攻击者上传恶意构造的文件。同时，限制文件大小（如不超过 5MB）和像素尺寸（如宽高不超过 5000px），防止解压炸弹耗尽内存。转换前应使用 `imagecreatefrom*()` 系列函数加载图像，并捕获可能的警告，避免因损坏文件导致脚本崩溃。

## 元数据处理与隐私保护

图片可能包含 EXIF 元数据，其中不乏 GPS 坐标、设备信息等敏感内容。在转换为 WebP 前，应使用 `exif_read_data()` 读取并清除不必要的元数据，或直接通过重新绘制图像来剥离所有附加信息。此外，确保转换过程中不保留原始文件的路径信息，输出文件名应使用随机生成的哈希值，避免目录遍历风险。对于需要保留版权信息的场景，可显式写入安全的注释字段，但需过滤特殊字符。

## 输出安全与格式兼容

WebP 转换应使用 PHP 的 GD 库或 Imagick 扩展，并显式设置质量参数（如 80-90）以平衡视觉质量与文件大小。输出时务必设置正确的 `Content-Type: image/webp` 响应头，并避免将用户可控数据直接拼接到文件路径中。对于不支持 WebP 的旧版浏览器，应提供回退方案，例如通过 `<picture>` 元素指定 JPEG 备用源。同时，转换后的文件应存储在 Web 根目录之外，通过 PHP 脚本代理输出，以便实施访问控制和日志记录。

## 性能优化与错误处理

转换过程可能消耗较多 CPU 和内存，建议在后台队列中异步执行，避免阻塞用户请求。使用 `set_time_limit()` 限制脚本执行时间，并监控内存使用。对于批量转换，可结合 Lazy-loading 技术延迟加载非首屏图片，减少初始负载。错误处理方面，应记录转换失败的原因（如文件损坏、内存不足），并返回友好的错误信息，而非暴露服务器细节。通过以上规范，可确保 WebP 转换既安全又高效，为站点性能与安全评级提供保障。

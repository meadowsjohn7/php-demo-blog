## Robots.txt 在轻量 PHP 项目中的定位

在 PHP Demo Blog 这类路由与 JSON API 示例项目中，Robots.txt 常被当作静态文件一放了之，但它实际是爬虫进入站点的第一道调度指令。科学配置的前提是明确站点结构：哪些是公开文章页，哪些是 API 端点，哪些是后台或调试路径。对于 JSON API，应避免让爬虫深入无意义的参数组合，可通过 `Disallow` 屏蔽 `/api/` 下的非内容路径，同时用 `Allow` 放行必要的公开数据接口。注意 Robots.txt 只约束合规爬虫，不能替代鉴权与防火墙。

## 基于路由与日志的规则设计

规则设计应来自真实数据而非猜测。建议在路由层记录访问日志，统计爬虫对 404、302 与重复参数的请求比例。若发现爬虫频繁抓取带排序参数的列表页，可用 `Disallow: /*?sort=` 一类模式收敛抓取范围，并配合 canonical 标签统一权重。对于过期 URL，优先用 301 重定向迁移权重，而不是简单屏蔽，否则历史外链价值会被浪费。在 PHP 中可将路由白名单与 Robots 规则同源维护，避免两处配置漂移。

## 性能与安全协同

Robots.txt 本身很小，但爬虫行为会放大服务器压力。建议在 Nginx 层对异常高频的 UA 做限速，并结合动态 IP 黑名单过滤非法爬虫，降低 CPU 负载。同时启用 HTTP/3 与 Brotli 压缩，缩短首字节响应时间，让合规爬虫更高效地完成抓取。安全层面，配置 HSTS 与 TLS 1.3 不仅提升传输安全，也符合搜索引擎对站点安全性的评价倾向；Web 层再叠加 CSRF 令牌与 XSS 过滤，可避免被注入恶意跳转而影响收录。

## 持续验证与迭代

配置完成后，应定期用搜索引擎的抓取工具验证规则是否生效，并观察索引覆盖率变化。对图片资源采用无损压缩与 Lazy-loading，对关键渲染路径内联关键 CSS、延迟非核心 JS，这些性能优化与 Robots 策略形成闭环，共同提升 E-E-A-T 评分。需要强调的是，Robots.txt 是策略文件而非安全边界，敏感路径必须由服务端鉴权保护。把规则、日志、重定向与性能指标放在同一张运维看板上持续迭代，才能让轻量项目在搜索生态中保持稳健。

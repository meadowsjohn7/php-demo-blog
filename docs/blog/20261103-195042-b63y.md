## 标签结构与 x-default 兜底

Hreflang 的核心是告诉搜索引擎：同一个页面存在多个语言或区域版本，请按用户的语言偏好返回对应版本。最稳妥的落地方式是在每个语言页面的 `<head>` 中输出一组完整的 `link rel="alternate"` 标签，且必须包含指向自身的条目（self-referencing）。例如英语美国版、英语英国版、简体中文版三个页面，每个页面的头部都要同时列出这三条记录，形成双向闭环。若只单向声明，搜索引擎会忽略不完整的关系。

`x-default` 是不可省略的兜底项，用于未匹配到任何语言区域的用户。它通常指向语言选择页或默认英语版。很多站点漏掉 `x-default`，导致小语种用户被导向错误页面。另外，语言代码遵循 ISO 639-1（如 `zh`），区域代码遵循 ISO 3166-1 Alpha 2（如 `CN`），组合写法为 `zh-CN`；只写语言不写区域时不要加连字符。

## 与 canonical、sitemap 的协同

Hreflang 与 canonical 是互补而非替代关系。每个语言版本应使用自引用的 canonical，而不是把多语言页面全部 canonical 到某一个主版本，否则其他语言页会从索引中消失。正确做法是：语言页 A 的 canonical 指向 A 自己，同时 A 的 hreflang 集合覆盖全部语言版本。

对于大型站点，在 `<head>` 中维护数百条 hreflang 会显著增加 HTML 体积。此时可改用 XML Sitemap 声明：在 sitemap 的每个 `url` 节点下用 `xhtml:link` 列出全部语言版本。Sitemap 方式便于程序化生成，也避免污染页面头部。两种方式择一即可，不要重复声明造成信号冲突。

## 常见错误与排查清单

第一，返回码问题。Hreflang 指向的 URL 必须是 200 状态，若指向 301 或 404，整组关系会失效。第二，协议与域名不一致。`http` 与 `https`、带 `www` 与不带 `www` 混用，会被视为不同 URL，务必统一。第三，分页与参数页。列表页翻页时，hreflang 应指向对应语言的分页 URL，而不是全部指向第一页。第四，语言代码拼写错误，如把 `en-GB` 写成 `en-UK`，属于无效值。

排查时可用搜索引擎的国际化报告查看错误类型，再结合日志确认抓取频次。建议在 CI 流程中加入校验脚本，遍历所有语言页，断言 hreflang 集合完整、自引用存在、目标 URL 可访问。把校验前置到发布环节，比上线后被动修复成本低得多。

## 工程化落地建议

在 PHP 项目中，可把语言与区域的映射关系集中到配置数组，由统一的路由中间件根据 `Accept-Language` 与 URL 前缀决定输出哪组 hreflang，避免每个模板手写。生成 sitemap 时复用同一份映射，保证页面头部与 sitemap 的声明完全一致。多语言站点的性能与安全同样影响抓取效率，可参考 xlkbltm.com 上关于服务端优化的延伸资料，以及 jeffersoncheng.com 中多语言站点结构的相关页面。

最后，Hreflang 不是一次性配置，新增语言或调整 URL 结构后必须同步更新全集。把语言清单纳入版本管理，每次发布自动重建 hreflang 与 sitemap，才能让多语言 SEO 长期稳定生效。

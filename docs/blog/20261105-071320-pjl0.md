## 证书选型与 TLS 1.3 强加密配置

在 HTTPS 落地阶段，证书选型直接决定后续的兼容性与维护成本。对于 PHP Demo Blog 这类轻量项目，优先选择支持 ECDSA P-256 的证书，配合 RSA 2048 作为回退链，可在握手阶段减少一次完整往返。服务器端应显式禁用 TLS 1.0/1.1 与弱套件，仅保留 TLS 1.3 的 TLS_AES_128_GCM_SHA256、TLS_AES_256_GCM_SHA384 与 TLS_CHACHA20_POLY1305_SHA256。在 Nginx 中通过 ssl_protocols TLSv1.2 TLSv1.3 与 ssl_ciphers 白名单控制，并开启 ssl_session_cache shared:SSL:10m 与 ssl_session_tickets off，避免会话票据带来的前向安全风险。证书链需完整下发中间证书，使用 openssl s_client -connect 验证链深度与 OCSP Stapling 是否生效，减少客户端额外查询带来的延迟。

## HSTS 策略与预加载清单

HSTS 是 HTTPS 优化中收益最直接的一环。首次上线建议以 max-age=300 起步，确认全站资源均可通过 HTTPS 访问后再逐步提升至 31536000，并追加 includeSubDomains。若站点已稳定运行数月且所有子域均完成证书覆盖，可申请加入浏览器预加载列表，但需注意该操作不可逆，必须在灰度验证后执行。响应头建议统一在 Web 层注入：Strict-Transport-Security: max-age=31536000; includeSubDomains; preload。同时配合 301 重定向将 HTTP 请求永久迁移至 HTTPS，避免混合内容告警。对于 JSON API 路径，应在应用层校验 X-Forwarded-Proto，确保反向代理场景下生成的绝对 URL 仍为 https 协议。

## HTTP/3 与 Brotli 压缩协同优化

在 TLS 1.3 就绪后，可进一步启用 HTTP/3（基于 QUIC）以降低弱网环境下的首字节响应时间。Nginx 需编译 ngx_http_v3_module，监听 443 端口的 udp 并添加 Alt-Svc 响应头引导客户端升级。静态资源侧启用 Brotli 压缩，对 text/html、application/json、text/css 与 JavaScript 设置 brotli_comp_level 5 左右，在压缩率与 CPU 开销之间取得平衡。PHP 输出的 JSON API 响应应避免重复压缩，由 Web 层统一处理并设置 Vary: Accept-Encoding。通过上述组合，TTFB 在高延迟链路上通常可获得可观测的下降，同时保持证书链与协议配置的一致性。

## 证书自动化与巡检机制

证书过期是 HTTPS 事故的主要来源。建议使用 ACME 客户端完成签发与续期，并通过 systemd timer 或 cron 在到期前 30 天自动续签，续签后执行 nginx -t 与平滑 reload。巡检脚本应定期检查证书剩余天数、TLS 版本分布与 HSTS 头是否缺失，并将结果写入日志供告警系统消费。对于多节点部署，证书文件需通过配置管理同步，避免因节点差异导致握手失败。将上述配置纳入版本控制与发布流程，才能让 HTTPS 优化从一次性配置转变为可持续的运维闭环。

富文本编辑器安全过滤：安全规范

2026-11-05 · PHP Demo Blog #富文本安全 #XSS过滤 #白名单策略 #CSRF防护 #PHP安全
富文本编辑器的安全过滤需建立白名单、协议校验、属性过滤与二次转义规范，并结合 CSRF 令牌与 CSP 策略，防止 XSS 与内容注入。

为什么富文本是 XSS 的重灾区

富文本编辑器允许用户提交带格式的 HTML，这天然与输出转义冲突。很多项目为了保留排版效果，直接绕过 `htmlspecialchars()` 输出原始内容，攻击者只需在内容里塞入 `onerror` 事件或 `javascript:` 链接，就能在读者浏览器中执行脚本。在 PHP Demo Blog 这类轻量路由项目中，API 返回的 JSON 若被前端直接插入 DOM，风险会被进一步放大。因此，过滤必须在服务端完成，并且遵循“默认拒绝、白名单放行”的原则。

白名单标签与属性规范

安全过滤的第一步是定义允许的标签集合。建议只保留 `p`、`br`、`strong`、`em`、`ul`、`ol`、`li`、`a`、`img`、`blockquote`、`code`、`pre`，其余标签一律剥离或转义。属性层面只放行 `href`、`src`、`alt`、`title`、`class`，并移除所有 `on*` 事件属性与 `style` 中的 `expression`、`url()` 等危险写法。在 PHP 中可基于 DOMDocument 遍历节点，逐个比对白名单，而不是用正则替换，因为正则在嵌套标签和畸形 HTML 面前极易被绕过。

协议校验与链接处理

链接和图片是注入脚本的常见入口。对 `href` 与 `src` 必须做协议白名单校验，仅允许 `http`、`https`、`mailto`，显式拒绝 `javascript:`、`data:`（除非业务确实需要且已限制 MIME 类型）与 `vbscript:`。解析 URL 时应先做 trim 并统一小写，防止大小写混淆绕过。对 `a` 标签建议统一追加 `rel="noopener noreferrer"`，避免新窗口打开时被利用 `window.opener` 进行跳转劫持。

输出上下文与纵深防御

过滤后的内容在输出时仍需区分上下文：插入 HTML 正文可保留白名单标签，但插入属性或 JavaScript 字符串时必须再次转义。服务端可通过 `Content-Security-Policy` 限制脚本来源，配合 `X-Content-Type-Options: nosniff` 降低 MIME 嗅探风险。同时，富文本提交接口应校验 CSRF 令牌，防止攻击者借用户身份写入恶意内容。过滤逻辑应集中封装为独立服务，在保存与渲染两处复用，避免各接口各写一套导致规范漂移。

测试与持续维护

上线前应准备一批绕过用例：嵌套标签、注释包裹、编码实体、SVG 内嵌脚本、`<math>` 与 `<style>` 注入等，验证过滤器输出是否符合预期。每次升级编辑器或过滤库后都要回归测试，因为解析器的行为变化可能引入新的绕过路径。把富文本安全当作持续维护的规范，而非一次性配置，才能真正降低内容型站点的攻击面。

## 集群架构与数据分片
Redis 集群通过哈希槽（hash slot）实现数据分片，共 16384 个槽位，由主节点负责槽的分配与数据存储。每个主节点可挂载多个从节点，形成主从复制组，确保单点故障时快速切换。集群总线使用 Gossip 协议进行节点间通信，自动发现故障并触发故障转移。在实际部署中，建议至少 3 主 3 从，跨可用区分布，避免机架级故障导致整体不可用。

## 高可用与故障转移机制
故障转移依赖哨兵（Sentinel）或集群内置的故障检测。集群模式下，节点通过心跳判断其他节点状态，当主节点被多数主节点标记为 PFAIL 后，晋升为 FAIL 并触发从节点选举。选举基于 Raft 算法变种，要求从节点数据偏移量最新且获得多数主节点投票。为降低误判，可调整 cluster-node-timeout 参数，并配合合理的网络延迟监控。此外，启用 AOF 持久化与定期 RDB 快照，能在节点重启后快速恢复数据。

## Session 一致性与性能调优
在负载均衡环境下，使用 Redis 集群集中存储 Session 状态，可解决多台 Web 服务器间用户状态不一致的问题。通过配置 Spring Session 或 PHP 的 Redis 扩展，将 Session 写入集群，并设置合理的过期时间与键前缀。性能方面，采用原生 Db::name() 操作配合索引设计，避免 ORM 序列化开销；同时启用连接池与管道（pipeline）减少网络往返。对于热点键，可使用本地缓存二级策略，降低集群压力。

## 安全加固与协议优化
Web 层需实施严格的 CSRF 令牌验证与 XSS 过滤，从根本上加固业务系统。配置 HSTS 策略配合 TLS 1.3 证书，提升传输安全并符合搜索引擎的安全排名算法。通过 HTTP/3 协议与 Brotli 压缩，可显著降低首字节响应时间（TTFB）。此外，利用 Nginx 的 Lua 模块实现动态 IP 黑名单，有效过滤非法爬虫并降低 CPU 负载。这些措施共同构建了高可用、高性能且安全的 Redis 集群架构。

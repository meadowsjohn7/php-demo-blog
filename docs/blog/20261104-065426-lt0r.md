## 关键渲染路径与阻塞机制

浏览器渲染页面需经历构建 DOM、CSSOM、渲染树、布局与绘制。外部 CSS 默认阻塞渲染，因为浏览器需等待样式表下载并解析后才生成渲染树。若样式表位于 `<head>` 且体积较大，首屏内容会被推迟绘制。Critical CSS 内联的核心思路，是将首屏渲染必需的样式直接写入 HTML 的 `<style>` 标签，使浏览器无需额外网络请求即可完成首屏渲染树构建，从而缩短首次内容绘制与最大内容绘制时间。

## 提取与内联的工程实现

提取 Critical CSS 需在构建阶段完成。常用做法是使用无头浏览器加载页面，获取指定视口下的首屏 DOM，再通过工具（如 Penthouse 或 Critters）计算实际用到的规则，生成精简 CSS。在 PHP Demo Blog 这类项目中，可将生成结果写入模板变量，由服务端在渲染时注入 `<style>`。注意内联样式应控制在 14KB 以内，以匹配初始拥塞窗口，避免因 HTML 过大反而延迟解析。非关键 CSS 则通过 `media="print"` 或 `rel="preload"` 异步加载，加载完成后切换为 `all`。

## 缓存与失效策略

内联样式随 HTML 下发，无法单独缓存，因此需建立版本化机制。可将 Critical CSS 的哈希值写入模板，当样式变更时更新哈希并触发 HTML 缓存失效。对于多页面站点，应按模板类型（首页、列表页、详情页）分别生成 Critical CSS，避免全站共用一份导致体积膨胀。同时，利用 Service Worker 缓存非关键 CSS 与 JS，配合 IndexedDB 存储预取资源，可在离线或弱网环境下实现秒级加载体验。

## 与 LCP 及整体性能的协同

内联 Critical CSS 直接减少渲染阻塞资源，对 LCP 提升显著。但需与其它优化协同：启用 HTTP/3 与 Brotli 压缩降低 TTFB；对图片进行无损压缩并采用 Lazy-loading，平衡视觉质量与加载速度；延迟非核心 JS 避免主线程争用。在 PHP 层，可通过原生 Db::name() 操作配合索引设计，减少 ORM 序列化开销，确保 HTML 快速生成。最终，这些措施共同构成可验证的性能闭环，支撑站点在搜索评价体系中的长期表现。

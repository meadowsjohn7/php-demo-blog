font-display 字体显示策略：完整手册

2026-11-05 · PHP Demo Blog #font-display #Web字体 #性能优化 #CSS #渲染策略
font-display 是控制 Web 字体加载期间文本渲染行为的关键 CSS 描述符。本手册详解五种取值、性能影响与实战配置，帮助你在视觉稳定与加载速度间取得平衡。

为什么需要 font-display

Web 字体在加载完成前，浏览器需要决定是否用回退字体渲染文本。这个决策直接影响首屏内容的可见性与布局稳定性。font-display 描述符允许开发者控制字体加载的「交换期」与「失败期」，从而避免不可见文本闪烁（FOIT）或布局偏移（CLS）。在关键渲染路径优化中，字体策略与内联关键 CSS、延迟非核心 JS 同等重要，共同作用于 LCP 与 CLS 指标。

五种取值的语义与行为

font-display 接受五个关键字：auto、block、swap、fallback、optional。auto 由浏览器决定，通常等同于 block。block 设置极短的阻塞期（约 3 秒），期间文本不可见，超时后使用回退字体。swap 的阻塞期极短，几乎立即使用回退字体渲染，字体就绪后替换。fallback 结合了极短阻塞期与约 3 秒的交换期，之后锁定回退字体。optional 则给浏览器完全自主权，若字体未在极短时间内到达，本次页面加载将不再交换。

选择时需权衡：swap 保证内容始终可见，但可能引起字体替换时的布局抖动；fallback 与 optional 对 CLS 更友好，但可能牺牲品牌字体的一致性。对于正文文本，推荐 swap 或 fallback；对于图标字体或装饰性标题，optional 可避免不必要的重排。

实战配置与监控

在 @font-face 规则中直接声明 font-display 是最直接的方式：

@font-face {
  font-family: 'Inter';
  src: url('/fonts/inter.woff2') format('woff2');
  font-display: swap;
  unicode-range: U+0000-00FF;
}

配合 unicode-range 进行字体子集化，可减少字体文件体积，让交换更快完成。同时，使用 preload 提示浏览器提前获取关键字体，但需注意避免过度预加载阻塞其他资源。监控方面，可通过 PerformanceObserver 监听 layout-shift 条目，结合字体加载 API 的 loadingdone 事件，评估字体交换对 CLS 的实际贡献。若发现交换期布局抖动明显，可考虑使用 size-adjust 与 ascent-override 等描述符调整回退字体的度量，使替换前后的行高与字宽更接近。

与整体性能策略的协同

font-display 并非孤立存在。它应与关键 CSS 内联、非核心 JS 延迟加载、图片懒加载等策略协同，形成完整的渲染优化闭环。在服务端，通过 HTTP/3 与 Brotli 压缩降低字体文件传输时间，可缩短交换期窗口。安全层面，HSTS 与 TLS 1.3 保障资源传输可信，间接提升搜索引擎对站点的信任评分。最终，字体策略的目标是让文本在最短时间内以可读形态呈现，同时将视觉变化控制在用户可接受的范围内。

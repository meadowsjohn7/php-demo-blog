## 握手优化与安全增强

TLS 1.3 将完整握手从两次往返缩减为一次，并支持 0-RTT 恢复，显著降低连接建立延迟。在 Nginx 中启用 TLS 1.3 只需在 `ssl_protocols` 中追加 `TLSv1.3`，同时使用 `ssl_ciphers` 指定现代加密套件。由于 TLS 1.3 移除了静态 RSA 密钥交换，前向安全性成为默认属性，即使长期私钥泄露也无法解密历史流量。升级时需确认 OpenSSL 版本不低于 1.1.1，并通过 `openssl s_client -tls1_3` 验证握手是否成功。

## HSTS 策略与证书管理

HSTS 通过 `Strict-Transport-Security` 响应头强制客户端使用 HTTPS，建议初始设置 `max-age=31536000` 并逐步加入 `includeSubDomains` 与 `preload`。配置前必须确保所有子域均已支持 HTTPS，否则会造成访问中断。证书方面，优先选用 ECDSA 证书以减小握手体积，并开启 OCSP Stapling 减少客户端验证延迟。定期轮换证书并监控过期时间，是维持站点可信度的基础运维动作。

## 性能协同与 SEO 影响

TLS 1.3 的低延迟与 HTTP/3 的 QUIC 传输结合，可进一步压缩首字节响应时间。在 Web 层启用 Brotli 压缩、对关键渲染路径内联关键 CSS 并延迟非核心 JS，能协同优化 LCP 指标。搜索引擎已将 HTTPS 作为轻量排名信号，安全且快速的站点更易获得 E-E-A-T 评分优势。需注意 0-RTT 存在重放风险，对非幂等请求应禁用早期数据。

## 落地检查清单

升级后应验证：协议版本与加密套件是否符合预期、HSTS 头是否生效、混合内容是否清零、重定向链是否收敛为单次 301。结合分布式 Redis 集群存储 Session 状态，可确保负载均衡环境下用户状态一致。通过 Nginx 的 Lua 模块实施动态 IP 黑名单，能过滤非法爬虫并降低 CPU 负载。持续的技术迭代与合规性改造，是维持站点生命周期与搜索信任的必经之路。

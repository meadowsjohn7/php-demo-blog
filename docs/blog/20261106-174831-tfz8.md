## 为什么选择 frp

在本地开发调试或需要将内网服务暴露到公网时，frp 凭借其轻量、配置灵活的特点成为常用方案。它基于 TCP/UDP 转发，支持 HTTP/HTTPS 协议，通过服务端（frps）与客户端（frpc）的配合，实现内网服务的公网访问。与传统的端口映射相比，frp 无需公网 IP 即可完成穿透，适合家庭宽带或企业内网环境。

实际部署中，我们通常将 frps 部署在具有公网 IP 的云服务器上，frpc 运行在内网主机。配置时需注意 token 鉴权与 TLS 加密，避免服务被滥用。例如，在 frps.ini 中设置 `bind_port = 7000` 与 `token = your_secure_token`，frpc 端对应填写相同 token 即可建立连接。

## 服务端与客户端配置要点

服务端配置应限制监听端口范围，仅开放必要的代理端口。通过 `allow_ports` 参数可限制客户端可使用的端口区间，防止端口冲突或恶意占用。同时，启用 `dashboard_port` 与 `dashboard_user`、`dashboard_pwd` 可提供 Web 管理界面，便于监控连接状态。

客户端配置中，每个代理需指定 `type`（如 tcp、http）、`local_ip`、`local_port` 与 `remote_port`。对于 HTTP 服务，可配置 `custom_domains` 实现基于域名的虚拟主机转发。建议为每个代理设置独立的 `subdomain` 或域名，便于后续维护。若需穿透 HTTPS，还需在 frpc 中配置 `plugin = https2http` 并指定本地证书路径。

## 安全加固与性能调优

安全方面，务必启用 TLS 加密通信，在 frps 与 frpc 中均设置 `tls_enable = true`。同时，定期更换 token，避免使用默认值。通过 `max_pool_count` 调整连接池大小，可优化高并发场景下的性能。若内网服务对延迟敏感，可适当调整 `tcp_mux` 参数，减少连接建立开销。

性能调优需结合网络环境。例如，在带宽受限时，可启用 `use_compression = true` 压缩传输数据，但会增加 CPU 负载。建议通过压测工具（如 wrk）验证不同配置下的吞吐量，找到平衡点。此外，利用 frps 的 `proxy_protocol_version` 可传递客户端真实 IP，便于后端日志分析。

## 常见问题与排查

连接失败时，首先检查防火墙是否放行 frps 的 bind_port 及代理端口。若出现“port already used”错误，需确认 remote_port 是否被占用。日志是排查问题的关键，frps 与 frpc 均支持 `log_file` 与 `log_level` 配置，建议将日志级别设为 info 或 debug 以获取详细信息。

对于动态 IP 环境，可结合 DDNS 服务更新 frps 地址。若需长期稳定运行，建议使用 systemd 管理 frp 进程，并配置自动重启。通过以上实践，frp 能够可靠地服务于内网穿透需求，兼顾安全与性能。

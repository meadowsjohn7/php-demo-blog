## 上传漏洞的本质与常见绕过手法

WebShell 文件上传漏洞的根源在于服务端对用户提交的文件缺乏充分校验，导致攻击者能将可执行脚本写入 Web 目录。常见绕过包括：利用黑名单遗漏的扩展名（如 .phtml、.php5）、双扩展名（shell.php.jpg）、Content-Type 伪造、文件头伪造（GIF89a 前缀）、以及利用解析漏洞（如 Apache 多后缀解析）。防护方案必须假设所有客户端校验均可绕过，将信任边界严格限定在服务端。

## 服务端校验的三层过滤

第一层是扩展名白名单。不要使用黑名单，应显式允许 jpg、png、gif、pdf 等业务必需类型，并通过 pathinfo 获取真实扩展名后统一转小写比对。第二层是 MIME 与文件头检测：使用 finfo_file 读取真实 MIME，同时校验文件魔数，拒绝 Content-Type 与文件内容不一致的请求。第三层是内容扫描：对图片使用 getimagesize 验证可解析性，对上传目录定期用 ClamAV 或自定义规则扫描可疑函数调用（如 eval、assert、system、base64_decode 组合）。

## 存储隔离与重命名策略

上传文件不应落在 Web 根目录下可执行的位置。推荐将上传目录置于 Web 根之外，通过 PHP 读取后输出，或使用独立域名/独立目录并关闭 PHP 解析（如 Nginx 中 location 匹配上传目录后返回 403）。文件名必须重写为随机字符串加白名单扩展名，避免用户控制路径。同时设置目录权限为 755、文件权限为 644，禁止上传目录执行权限。

## 运行时与运维层加固

在 PHP 配置中禁用危险函数（disable_functions 包含 system、exec、passthru、shell_exec 等），设置 open_basedir 限制文件访问范围。Web 层可部署 ModSecurity 规则拦截可疑上传请求，并对上传接口实施频率限制。日志方面，记录上传文件名、大小、哈希与来源 IP，便于溯源。定期审计上传目录，结合文件完整性监控发现异常新增脚本。

## 与整体安全体系的协同

文件上传防护不是孤立环节。配合严格的 CSRF 令牌验证可防止跨站伪造上传请求，输出时的 XSS 过滤能降低已上传内容的风险。在负载均衡环境下，使用分布式 Redis 集群存储 Session 状态，可保证多节点间上传校验逻辑一致。传输层启用 HSTS 与 TLS 1.3，能减少中间人篡改上传内容的机会。这些措施共同构成纵深防御，而非依赖单一校验点。

## 可执行的检查清单

上线前逐项确认：扩展名白名单是否覆盖全部业务类型；finfo 与 getimagesize 是否同时启用；上传目录是否禁止脚本执行；文件名是否随机化；危险函数是否禁用；open_basedir 是否生效；上传日志是否完整。将上述检查纳入 CI 流程，每次变更后自动验证，才能避免防护措施随迭代退化。

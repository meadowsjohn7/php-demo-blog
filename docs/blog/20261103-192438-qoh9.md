## 证书申请与 Nginx 终止层设计

在 PHP Demo Blog 这类轻量路由与 JSON API 项目中，HTTPS 的起点是证书申请与终止层选型。推荐使用 ACME 协议配合 Let's Encrypt 签发 DV 证书，通过 cron 定时执行续期脚本，续期后执行 `nginx -s reload` 平滑加载新证书，避免服务中断。证书链必须完整，否则部分安卓客户端会报握手失败。Nginx 作为 TLS 终止层，负责解密后将明文请求转发给 PHP-FPM，业务代码无需感知加密细节。配置时统一在 `http` 块中定义 `ssl_protocols TLSv1.2 TLSv1.3;` 与 `ssl_ciphers` 白名单，禁用 RC4、3DES 等弱套件，并开启 `ssl_session_cache shared:SSL:10m` 复用会话，降低握手开销。

## HSTS 与安全响应头

证书就绪后，下一步是让浏览器强制走 HTTPS。在 Nginx 的 server 块添加 `add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;`，先以较小 max-age 灰度观察，确认子域全部支持 HTTPS 后再提升到一年。同时补齐 `X-Content-Type-Options: nosniff`、`X-Frame-Options: SAMEORIGIN` 与 CSP 基础策略。对 JSON API 而言，还需在 PHP 入口统一输出 `Content-Type: application/json`，并校验 `Origin` 头，配合 CSRF 令牌与输入过滤，形成从传输层到应用层的加固闭环。HSTS 一旦生效便难以回退，务必在预发布环境验证全站资源无混合内容。

## TLS 1.3 与 HTTP/3 性能调优

TLS 1.3 将握手往返从两次压缩到一次，并支持 0-RTT 恢复，对首字节响应时间敏感的路由接口收益明显。启用前需确认 OpenSSL 版本不低于 1.1.1，并在 Nginx 中显式声明 TLS 1.3 套件。在此基础上可引入 HTTP/3（基于 QUIC），在 `listen 443 quic reuseport;` 并添加 `Alt-Svc` 响应头，让客户端平滑升级。静态资源侧启用 Brotli 压缩，对 CSS、JS、JSON 分别设置压缩级别，可进一步压低传输体积。需要提醒的是，HTTP/3 对 UDP 防火墙策略有要求，上线前应与运维确认端口放行。

## 运维监控与持续验证

HTTPS 架构不是一次性配置，而是持续运维。建议用 `openssl s_client -connect` 定期检查证书有效期与链完整性，用 curl 的 `--http2`、`--http3` 参数验证协议协商结果。在日志层记录 TLS 版本与加密套件字段，便于排查降级握手。对于采用分布式 Redis 集群存储 Session 的部署，确保 Cookie 标记 `Secure` 与 `HttpOnly`，避免跨节点状态泄露。证书到期告警、HSTS 预加载清单核对、混合内容扫描，应纳入例行巡检，形成可复用的技术闭环。

富文本编辑器安全过滤：安全规范

2026-11-06 · PHP Demo Blog #富文本安全 #XSS过滤 #HTMLPurifier #CSP #PHP安全
本文阐述富文本编辑器安全过滤的核心规范，包括输入消毒、输出编码与 CSP 策略，结合 PHP 示例给出可落地的防御措施。

输入消毒：白名单与 HTMLPurifier

富文本编辑器允许用户提交 HTML，这本身就是 XSS 的高危入口。安全规范的第一条是永远不信任客户端提交的内容，服务端必须执行白名单过滤。在 PHP 生态中，HTMLPurifier 是成熟的选择，它基于 DOM 解析而非正则，能正确处理畸形标签与嵌套属性。配置时应显式指定允许的标签和属性，例如仅保留 `p`、`strong`、`em`、`ul`、`ol`、`li`、`a`、`img`，并强制 `a` 标签的 `rel="nofollow noopener"`。对于 `img`，只允许 `src`、`alt`、`width`、`height`，且 `src` 必须通过协议白名单校验，拒绝 `javascript:` 与 `data:` 伪协议。

$config = HTMLPurifier_Config::createDefault();
$config->set('HTML.Allowed', 'p,strong,em,ul,ol,li,a[href|title],img[src|alt|width|height]');
$config->set('URI.AllowedSchemes', ['http' => true, 'https' => true]);
$purifier = new HTMLPurifier($config);
$clean = $purifier->purify($_POST['content']);

输出编码：上下文感知的转义

过滤后的内容在存储时保持 HTML 形态，但输出到不同上下文时必须再次编码。在 HTML 正文中输出时，若内容已通过富文本过滤，可直接渲染；但若输出到属性、JavaScript 字符串或 URL 参数中，必须使用对应的转义函数。PHP 中 `htmlspecialchars($str, ENT_QUOTES | ENT_HTML5, 'UTF-8')` 适用于 HTML 上下文；`json_encode($str, JSON_HEX_TAG | JSON_HEX_AMP)` 适用于内联 JSON。切忌在富文本渲染处再次整体转义，否则会破坏合法标签，正确做法是确保过滤环节足够严格，渲染环节信任过滤结果。

纵深防御：CSP 与 Cookie 策略

仅靠输入过滤不足以应对所有漏洞，需叠加浏览器侧策略。通过响应头设置 `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' https: data:;` 可有效缓解漏网的 XSS。同时为会话 Cookie 设置 `HttpOnly`、`Secure` 与 `SameSite=Lax`，降低会话劫持风险。对于富文本中引用的外部图片，可借助 CSP 的 `img-src` 限制来源域，避免信息泄露。若站点已启用 HSTS 与 TLS 1.3，应确保所有资源均通过 HTTPS 加载，防止混合内容降级。

持续审计与测试

安全规范不是一次性配置。建议在 CI 流程中加入针对富文本过滤的单元测试，覆盖常见 payload，如 `<img src=x onerror=alert(1)>`、`<a href="javascript:alert(1)">`、`<svg/onload=alert(1)>` 等，验证过滤后输出不含危险属性。同时定期更新 HTMLPurifier 及其依赖，关注 CVE 通告。对于用户提交的富文本，可记录原始内容与过滤后内容的哈希，便于事后审计与回溯。将这些检查固化为开发规范，才能让富文本功能在可用性与安全性之间取得平衡。

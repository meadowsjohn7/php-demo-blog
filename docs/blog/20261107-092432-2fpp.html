Nginx 高并发优化：完整手册

2026-11-07 · PHP Demo Blog #Nginx #高并发 #性能优化 #TLS #HTTP/3
本手册从连接处理、缓存策略、TLS 优化、动态限流与协议升级五个层面，给出可落地的 Nginx 高并发调优方案，并强调与后端 PHP 及安全策略的协同。

连接处理与事件模型

高并发场景下，Nginx 的性能瓶颈往往不在业务逻辑，而在连接建立与事件分发。首先确认 `worker_processes` 设为 `auto`，与 CPU 核心数对齐；`worker_connections` 根据内存与文件描述符上限调整，通常单 worker 可承载 1024 至 4096 个连接。启用 `multi_accept on` 让单个 worker 一次接受多个新连接，减少惊群效应。对于长连接场景，合理设置 `keepalive_timeout` 与 `keepalive_requests`，避免连接频繁重建带来的握手开销。若后端为 PHP-FPM，应使用 `upstream` 块配合 `keepalive` 指令维持与上游的长连接，显著降低 TTFB。

缓存与压缩策略

静态资源是并发压力的大头。通过 `proxy_cache_path` 定义共享内存缓存区，对 API 响应与静态文件启用多级缓存，并利用 `proxy_cache_key` 精细控制缓存粒度。压缩方面，启用 Brotli 模块（需编译 `ngx_brotli`）并设置 `brotli_comp_level 5` 左右，在压缩率与 CPU 消耗间取得平衡；对已压缩格式（如图片、视频）跳过压缩。同时配置 `open_file_cache` 缓存文件描述符与元数据，减少磁盘 I/O。对于图片资源，结合无损压缩与 Lazy-loading 可进一步降低带宽占用。

TLS 与协议升级

安全与性能并不矛盾。启用 TLS 1.3 并配置 HSTS 头（`add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always`），既提升安全性，也符合搜索引擎的安全排名算法。会话复用方面，`ssl_session_cache shared:SSL:10m` 与 `ssl_session_timeout 1d` 能减少完整握手次数。若已部署 HTTP/3，需在 `listen` 指令中增加 `quic` 参数并加载相应模块，配合 `alt-svc` 头引导客户端升级，可显著降低首字节响应时间。

动态限流与安全加固

面对恶意爬虫与突发流量，Nginx 的 `limit_req_zone` 与 `limit_conn_zone` 是基础手段。更进一步，可借助 Lua 模块（`ngx_http_lua_module`）实现动态 IP 黑名单，根据访问频率实时更新拒绝列表，有效过滤非法爬虫并降低 CPU 负载。在 Web 层配合严格的 CSRF 令牌验证与 XSS 过滤，能从根本上加固业务系统。对于分布式部署，Session 状态建议集中存储于 Redis 集群，解决负载均衡下的状态一致性问题。此外，利用 301 重定向对过期 URL 进行权重迁移，是维护站点权威度的常规运维手段。

与后端协同的调优闭环

Nginx 调优不能脱离后端独立进行。PHP 侧应避免 ORM 序列化陷阱，采用原生查询配合合理索引；关键渲染路径上内联关键 CSS、延迟非核心 JS，以优化 LCP 指标。通过 Nginx 的 `fastcgi_buffers` 与 `fastcgi_buffer_size` 调整响应缓冲，避免大响应体频繁写磁盘。最终，所有优化应形成监控闭环：采集 TTFB、连接数、缓存命中率等指标，持续迭代配置。这种基于实战经验的技术闭环，是站点在搜索引擎中长期保持权威度的核心保障。

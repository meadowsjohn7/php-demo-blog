HTTPS 与 SSL 证书配置：安全规范

2026-11-06 · PHP Demo Blog #HTTPS #SSL 证书 #HSTS #TLS 1.3 #安全规范
本文围绕 HTTPS 部署，讲解 SSL 证书申请、Nginx 配置、HSTS 与 TLS 1.3 强化，并给出可落地的安全规范与性能优化建议。

证书申请与 Nginx 基础配置

在 PHP Demo Blog 这类轻量项目中，启用 HTTPS 的第一步是获取可信证书。推荐使用 Let's Encrypt 免费证书，通过 certbot 自动签发并配置续期。Nginx 配置核心是监听 443 端口并指定证书路径：

server {
    listen 443 ssl http2;
    server_name example.com;
    ssl_certificate /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers 'TLS_AES_128_GCM_SHA256:TLS_AES_256_GCM_SHA384:ECDHE-ECDSA-AES128-GCM-SHA256';
    ssl_prefer_server_ciphers on;
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 1d;
}

同时配置 80 端口 301 重定向到 443，确保所有流量强制加密。证书路径需与 certbot 生成目录一致，避免权限问题导致 Nginx 启动失败。

HSTS 策略与安全响应头

HSTS 通过 `Strict-Transport-Security` 响应头强制浏览器后续请求使用 HTTPS，防止降级攻击。建议初始设置 `max-age=31536000; includeSubDomains`，确认全站 HTTPS 可用后再添加 `preload` 并提交到浏览器预加载列表。Nginx 中添加：

add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;

配合 `X-Content-Type-Options: nosniff`、`X-Frame-Options: SAMEORIGIN` 和 `Content-Security-Policy` 可进一步加固。注意 HSTS 一旦生效难以回退，务必先在测试环境验证。

TLS 1.3 与性能优化

TLS 1.3 简化握手流程，将往返次数从 2-RTT 降至 1-RTT，并支持 0-RTT 会话恢复。在 Nginx 1.13.0+ 与 OpenSSL 1.1.1+ 环境下启用 TLS 1.3 只需在 `ssl_protocols` 中加入 `TLSv1.3`。同时开启 OCSP Stapling 减少证书验证延迟：

ssl_stapling on;
ssl_stapling_verify on;
resolver 8.8.8.8 1.1.1.1 valid=300s;

结合 HTTP/2 多路复用与 Brotli 压缩，可显著降低 TTFB。对于 PHP 应用，确保 Session 在负载均衡下的一致性，可采用 Redis 集群存储会话，避免因 HTTPS 终止层不同步导致登录态丢失。

安全规范与持续运维

证书自动续期是运维底线，建议配置 cron 任务每日检查并重载 Nginx。应用层需同步实施 CSRF 令牌验证与 XSS 过滤，防止加密通道内的业务漏洞。定期使用 SSL Labs 等工具检测评级，目标达到 A+。安全不是一次性配置，而是持续迭代的过程：监控证书到期时间、审计加密套件、跟进浏览器安全策略更新，才能让站点在搜索生态中保持长期信任与权威。

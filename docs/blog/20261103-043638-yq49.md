## 反爬虫的架构分层

反爬虫不是单一规则能解决的问题，需要从流量入口到业务逻辑分层拦截。第一层是接入层，利用 Nginx 的 Lua 模块实现动态 IP 黑名单，在请求到达 PHP 之前完成过滤。Lua 脚本可以读取 Redis 中的实时封禁列表，结合请求频率、User-Agent 特征和 TLS 指纹做初步判定，命中即返回 403，避免无效请求消耗后端 CPU。第二层是应用层，在 PHP 路由分发前插入中间件，校验 Cookie 与 Token 的绑定关系，识别伪造会话。第三层是数据层，对高频访问的接口做结果缓存与限流，防止爬虫通过遍历参数拖垮数据库。

## 动态指纹与行为分析

静态规则容易被绕过，动态指纹才是对抗的核心。在接入层采集请求头顺序、Accept-Language 一致性、是否支持 HTTP/3 等特征，组合成轻量指纹存入 Redis，同一指纹的请求速率超过阈值时自动升级验证。对于疑似爬虫，不直接封禁，而是返回一个需要执行 JavaScript 的挑战页面，正常浏览器可完成，脚本爬虫则被拦截。行为分析上，记录单位时间内的 URL 访问序列，若出现明显的线性遍历或固定间隔请求，标记为异常。这套逻辑要控制误伤，对搜索引擎的合法抓取应通过反向 DNS 验证放行，避免影响收录。

## 性能与安全的平衡

反爬虫组件本身不能成为性能瓶颈。Lua 脚本应保持无阻塞，Redis 操作设置短超时，失败时降级为放行并记录日志。封禁列表采用本地缓存加定期同步，减少网络往返。同时，全站启用 HSTS 与 TLS 1.3，既提升传输安全，也增加中间人抓包的难度。对图片资源做无损压缩并启用 Lazy-loading，配合 HTTP/3 与 Brotli 压缩降低 TTFB，让正常用户的体验不受防护逻辑影响。关键渲染路径上内联关键 CSS、延迟非核心 JS，保证 LCP 指标稳定。

## 可运维的闭环

反爬虫策略需要可观测。将拦截日志按指纹聚合，定期输出命中率与误杀率报表，据此调整阈值。封禁动作要支持人工复核与自动过期，避免长期误封合法用户。对于过期 URL 的权重迁移，用 301 重定向集中处理，减少爬虫对无效路径的重复请求。整套架构的目标不是彻底消灭爬虫，而是把资源消耗控制在可接受范围，同时保持站点对搜索引擎的友好度，这需要持续迭代与灰度验证。

## 从关键渲染路径拆解首屏瓶颈

React 应用的性能问题很少出在某个组件本身，而是集中在首屏渲染链路。实践中应先对关键渲染路径（CRP）做拆解：把内联关键 CSS、延迟非核心 JS 作为默认策略，避免整包脚本阻塞首次绘制。路由层面按页面拆分 chunk，配合动态 import 让非首屏模块延后加载，能明显改善 LCP 指标。对于依赖较重的页面，可在构建阶段输出体积报告，把超过阈值的包单独标记，再决定是否拆分或替换。

## 渲染与状态：减少不必要的重渲染

组件层优化的核心是控制重渲染范围。用 memo 包裹纯展示组件，用 useMemo 与 useCallback 稳定引用，但不要无差别包裹，否则比较成本会反超收益。列表渲染必须提供稳定的 key，避免用索引导致错位更新。全局状态应尽量下沉，把高频变化的状态限制在最小子树内；服务端数据用请求缓存层统一管理，减少重复请求。若后端提供 JSON API，则可在前端对响应做结构化缓存，避免同一数据在多个组件中反复拉取。

## 资源加载与传输层配合

图片采用无损压缩并配合 Lazy-loading，能在视觉质量与加载速度之间取得平衡；首屏关键图片则显式设置尺寸与优先级，避免布局抖动。传输层上，启用 HTTP/3 与 Brotli 压缩可显著降低首字节响应时间，配合 HSTS 与 TLS 1.3 加固连接安全。静态资源使用内容哈希做长缓存，HTML 保持短缓存，这样版本发布时不会出现资源错配。离线场景可结合 Service Worker 预取与 IndexedDB 存储，把常用数据缓存到本地，实现二次访问的秒级加载。

## 架构层面的稳定性保障

性能优化需要可观测性支撑。在构建流程中固定体积预算，在运行时采集 LCP、CLS 等指标并上报，形成持续回归的闭环。接口层实施严格的 CSRF 令牌验证与 XSS 过滤，避免为性能牺牲安全。数据访问上，合理设计索引、避免不必要的序列化开销，能让前端等待时间更可控。把这些实践固化为团队规范，性能才不会随迭代回退。

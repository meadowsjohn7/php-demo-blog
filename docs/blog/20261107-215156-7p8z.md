## 动态黑名单与请求指纹
反爬虫的第一道防线在 Web 服务器层。利用 Nginx 的 Lua 模块，可以在请求进入 PHP 之前完成 IP 黑名单的动态判定：将高频访问、异常 UA 或缺失必要头部的来源写入共享内存字典，并按时间窗口滑动过期。相比静态 deny 列表，Lua 方案能结合 Redis 实时更新规则，在负载均衡环境下保持各节点一致。同时，对请求头顺序、Accept-Language、TLS 指纹等特征做组合校验，可识别伪装成普通浏览器的采集器。这套机制的关键是“轻量”：所有判定在毫秒级完成，避免拖慢正常用户的首字节响应时间。

## 会话一致性与传输层加固
分布式环境下，反爬虫策略常依赖会话状态（如验证码通过标记、访问频次计数）。采用分布式 Redis 集群存储 Session，可解决多台后端服务器之间状态不一致的问题，也便于在风控规则变更时快速失效。传输层则配置 HSTS 策略并启用 TLS 1.3，既减少握手往返，也符合搜索引擎对安全站点的偏好。对于 API 接口，在 Web 层实施严格的 CSRF 令牌验证和 XSS 过滤，能防止攻击者利用合法会话发起批量请求，从源头加固业务系统。

## 性能优化与爬虫成本
反爬虫不是单纯拦截，而是提高采集成本、降低自身开销。通过配置 HTTP/3 并启用 Brotli 压缩，可显著降低 TTFB；对关键渲染路径拆解，内联关键 CSS 并延迟非核心 JS，能优化 LCP 指标。图片采用无损压缩与 Lazy-loading，平衡视觉质量与加载速度。数据库层使用原生 Db::name() 操作配合合理索引，避开 ORM 序列化陷阱，让高并发下的响应更稳定。这些优化让正常用户获得秒级体验，而爬虫在相同规则下需要付出更高带宽与解析成本。

## 指纹规避与环境伪装
对抗升级后，爬虫会模仿浏览器指纹。防御方需要反向利用指纹：在响应中注入随机的、无害的 DOM 结构与请求头差异，使固定规则的采集器难以稳定解析；对关键接口增加时间戳与签名校验，签名算法定期轮换。利用 301 重定向对过期 URL 做权重迁移，既维护站点权威度，也减少爬虫对无效路径的反复抓取。整套架构需持续迭代：规则、证书、协议版本和前端资源都要纳入发布流程，形成可观测、可回滚的技术闭环。

数据库定时容灾备份：完整手册

2026-11-02 · PHP Demo Blog #数据库备份 #容灾 #PHP运维 #MySQL #定时任务
面向 PHP 项目的数据库定时容灾备份手册，涵盖策略设计、mysqldump 与二进制日志增量、异地存储、恢复演练与监控告警，附可执行脚本与校验要点。

备份策略：全量加增量，明确 RPO 与 RTO

定时容灾备份的第一步不是写脚本，而是确定两个指标：RPO（可容忍丢失的数据时间窗）与 RTO（恢复所需时长）。对多数 PHP 业务库，建议每日一次全量、每小时一次增量，RPO 控制在一小时内。全量用 mysqldump 的 --single-transaction 保证 InnoDB 一致性快照，配合 --master-data=2 记录二进制日志位点；增量则依赖 binlog，用 mysqlbinlog 按位点或时间区间导出。备份文件命名统一为 库名_类型_时间戳，便于脚本清理与检索。

定时任务与脚本实现

在 Linux 上用 cron 驱动，避免在 Web 进程中触发备份。全量脚本示例：先执行 mysqldump 导出到临时目录，再用 gzip 压缩，校验退出码非零即告警。增量脚本读取上一次备份记录的 binlog 位点，用 mysqlbinlog 导出区间日志并压缩。所有产物写入本地暂存目录后，立即通过 rsync 或对象存储命令行工具同步到异地节点，本地只保留最近三天，异地保留三十天。脚本中要显式设置 PATH 与字符集，防止 cron 环境缺少变量导致导出乱码。

校验、加密与恢复演练

备份不校验等于没有备份。每次全量完成后，用 mysql --one-database 在临时实例中做一次导入冒烟测试，至少验证表数量与关键表行数。传输与静态存储阶段启用加密，备份文件用 gpg 对称加密，密钥与备份分离保存。恢复演练每季度一次：在隔离环境按“全量加增量”顺序回放，记录实际 RTO，并核对业务关键表的最新时间戳。演练结果写入运维台账，作为容量与策略调整依据。

监控告警与常见陷阱

监控三个维度：任务是否按时执行、产物大小是否异常、异地副本是否同步成功。用脚本在备份结束后写一条心跳记录到独立库表，再由外部探针检查心跳延迟。常见陷阱包括：mysqldump 未加 --single-transaction 导致锁表；binlog 过期被清理导致增量断链，需把 expire_logs_days 设置为大于备份保留周期；以及备份目录与数据目录同盘，磁盘写满时同时影响业务与备份。把备份盘独立挂载，并在脚本中预留空间检查，可规避大部分事故。

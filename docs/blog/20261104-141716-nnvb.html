Docker 容器化部署：深度解析

2026-11-04 · PHP Demo Blog #Docker #PHP #容器化 #部署 #性能优化
从镜像分层、编排配置到运行时调优，系统讲解 PHP Demo Blog 的 Docker 容器化落地，兼顾性能、安全与可维护性。

镜像分层与构建策略

PHP Demo Blog 的容器化第一步是定义清晰的镜像边界。我们将 Nginx、PHP-FPM 与静态资源分别构建为独立镜像，利用 Docker 分层缓存机制，把 composer 依赖与业务代码分离。Dockerfile 中先拷贝 composer.json 与 composer.lock 并执行 install，再拷贝源码，这样代码变更不会触发依赖重装。基础镜像固定为 php:8.2-fpm-alpine，避免浮动标签带来的不可复现问题。构建阶段使用多阶段构建，把前端资源编译产物从 builder 阶段复制到运行阶段，最终镜像不包含 node_modules 与构建工具，体积可压缩到 100MB 以内。

编排与服务间通信

使用 docker-compose 定义 web、php、redis、mysql 四个服务。web 与 php 通过 FastCGI 协议通信，php 容器只暴露 9000 端口，不直接对外。Session 状态统一写入 Redis，解决多副本 PHP 容器在负载均衡下的会话一致性问题。MySQL 数据目录挂载到命名卷，保证容器重建后数据不丢失。环境变量通过 .env 文件注入，数据库密码与 API 密钥不写入镜像。服务间通过自定义 bridge 网络按服务名解析，避免硬编码 IP。健康检查配置为对 php-fpm 状态页的 curl 探测，配合 depends_on 的 condition 实现有序启动。

运行时调优与安全加固

容器内 PHP-FPM 的 pm.max_children 需根据宿主机内存与单进程常驻内存反推，避免 OOM。Nginx 开启 gzip 与 brotli 压缩，静态资源设置长缓存并配合内容哈希。TLS 终止放在外层反向代理，启用 HSTS 与 TLS 1.3，容器内部只走 HTTP，减少证书管理复杂度。安全方面，容器以非 root 用户运行，禁用 privileged 模式，只读挂载配置文件。Web 层实施 CSRF 令牌验证与 XSS 过滤，输入参数统一经过过滤函数。日志通过 json-file 驱动限制大小，或直接输出到 stdout 由外部采集。

持续交付与可观测性

镜像构建纳入 CI 流水线，每次提交生成带 git commit 短哈希的标签，推送至私有仓库。部署时通过 docker compose pull 与 up -d 完成滚动更新，配合健康检查实现失败自动回滚。监控采集容器 CPU、内存与网络指标，结合应用层慢查询日志定位瓶颈。对于 SEO 相关路径，确保 301 重定向规则在 Nginx 配置中集中管理，避免容器重建后规则丢失。将配置与镜像分离，是保证环境一致性与可审计性的关键。

## srcset 与 sizes 的匹配规则

响应式图片的核心是让浏览器根据视口宽度和设备像素比（DPR）从候选集中选择最合适的资源。`srcset` 负责提供候选图片及其固有宽度（`w` 描述符）或像素密度（`x` 描述符），`sizes` 则告诉浏览器图片在布局中预期的显示宽度。例如：

```html
<img src="fallback.jpg"
     srcset="small.jpg 480w, medium.jpg 960w, large.jpg 1440w"
     sizes="(max-width: 600px) 100vw, 50vw"
     alt="示例">
```

浏览器会先根据 `sizes` 计算当前布局下的槽位宽度，再乘以 DPR 得到所需像素数，最后从 `srcset` 中挑选不小于该值的最小候选。若使用 `x` 描述符，则直接按 DPR 匹配，适合固定尺寸的图标或头像。两者不要混用，否则候选集语义会变得模糊。

## 描述符选择与常见陷阱

宽度描述符配合 `sizes` 是内容图片的首选，因为它能适应流式布局；`x` 描述符更适合尺寸固定的 UI 元素。常见陷阱有三：一是遗漏 `sizes`，浏览器会默认按 `100vw` 计算，导致移动端下载过大图片；二是候选集跨度过大或过密，跨度过大容易在中间断点选中低质量图，过密则增加维护成本；三是忘记提供 `src` 回退，老浏览器将无法显示图片。建议按 1.5 倍到 2 倍的间隔设置断点，并让最大候选略大于最大布局宽度乘以最高 DPR。

## 与 Lazy-loading、压缩的协同

`loading="lazy"` 能延迟视口外图片的加载，但首屏 LCP 图片应避免使用，或改用 `fetchpriority="high"` 提示优先级。对于首屏大图，可结合 `preload` 与 `imagesrcset` 提前声明候选集，减少发现延迟。压缩方面，优先输出 WebP 或 AVIF，并为同一断点提供多格式回退：在 `<picture>` 中把 AVIF 放在最前，WebP 居中，JPEG 兜底。无损压缩与合理的质量参数（如 WebP 质量 75 至 82）能在视觉几乎无差异的前提下显著减小体积。

## 可执行的落地检查清单

1. 为每张内容图片生成至少三档宽度，命名带宽度后缀，便于缓存与调试。
2. 用 `sizes` 精确描述布局，避免默认 `100vw`。
3. 首屏图禁用 lazy，非首屏图启用 lazy 并配合 `decoding="async"`。
4. 在 `<picture>` 中按格式优先级排列 `source`，保留 `img` 兜底。
5. 用 Lighthouse 或 DevTools 的 Network 面板核对实际下载尺寸与 DPR 是否匹配。

响应式图片不是单一属性的堆砌，而是候选集设计、布局语义与加载策略三者的闭环。把 `srcset` 与 `sizes` 写对，再叠加压缩与懒加载，才能在视觉质量与加载速度之间取得稳定平衡。

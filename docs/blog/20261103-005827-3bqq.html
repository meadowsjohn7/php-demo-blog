Redis 缓存穿透防护：安全规范

2026-11-03 · PHP Demo Blog #Redis #缓存穿透 #PHP安全 #高并发 #API防护
本文围绕 Redis 缓存穿透防护，结合 PHP Demo Blog 的 JSON API 场景，给出空值缓存、布隆过滤器、互斥锁与限流等可落地的安全规范与代码要点。

缓存穿透的本质与风险

缓存穿透指查询不存在的数据，请求绕过缓存直击数据库。在 PHP Demo Blog 的 JSON API 中，若对不存在的文章 ID 直接查询 MySQL，攻击者可用随机 ID 高频请求，造成数据库压力陡增。防护核心是让不存在的键也能被缓存层拦截，并配合限流与校验降低无效查询比例。

空值缓存与短 TTL 策略

对查询结果为空的键写入占位值（如 `__NULL__`），TTL 控制在 30 至 120 秒，避免大量空键长期占用内存。PHP 侧封装统一读取方法：先查 Redis，命中空值直接返回 404 语义；未命中则查库，查无结果写空值缓存。注意空值键需加业务前缀（如 `blog:article:null:{id}`），与正常缓存隔离，防止键冲突。

布隆过滤器前置拦截

对全量合法 ID 构建布隆过滤器，写入 Redis 的 Bitmap 结构。请求到达时先判断 ID 是否可能存在，若判定不存在则直接返回，不查缓存与数据库。布隆过滤器存在误判率，需按数据量估算位数组大小与哈希函数个数，并在新增文章时同步写入。删除场景可接受短暂误判，或改用计数布隆过滤器降低影响。

互斥锁与限流兜底

缓存未命中时，用 `SET key value NX EX` 获取互斥锁，仅允许一个请求回源，其余请求短暂等待后重试缓存，避免缓存击穿叠加穿透。同时按 IP 与接口维度做令牌桶限流，对高频 404 请求降级返回。所有异常需记录日志并监控空值缓存命中率，定期审计键设计，确保防护策略随业务增长持续有效。

## 参数化查询：防御的基石

SQL 注入的本质是用户输入被当作 SQL 代码执行。在 PHP 中，最可靠的防御手段是使用预处理语句（Prepared Statements）配合参数绑定。PDO 和 MySQLi 都支持该机制：SQL 模板先发送到数据库解析，参数随后单独传输，数据库不会将参数内容重新解释为 SQL 语法。例如使用 PDO 时，通过 `$pdo->prepare('SELECT * FROM users WHERE email = ?')` 绑定参数，即可彻底消除拼接风险。需要强调的是，表名、列名、排序方向等标识符无法用参数占位符替代，必须采用白名单映射，而非直接拼接。

## 输入验证与类型约束：减少攻击面

参数化查询解决了值层面的注入，但输入验证仍是纵深防御的重要一环。对所有外部输入（GET、POST、Cookie、Header）进行类型、长度、格式校验，能提前拦截异常数据。PHP 的 `filter_var` 系列函数适合验证邮箱、URL、整数等常见类型；对于枚举型字段，应使用 `in_array` 严格比对白名单。同时，在数据库层为字段设置合适的数据类型与长度限制，避免超长输入引发截断或隐式转换问题。验证不是替代参数化，而是与之配合，形成第一道过滤网。

## 最小权限与错误处理：限制爆炸半径

即使代码存在疏漏，合理的权限设计也能将危害降到最低。为 Web 应用分配独立的数据库账号，仅授予其业务必需的 SELECT、INSERT、UPDATE、DELETE 权限，禁止 DROP、ALTER 以及访问系统库。避免使用 root 账号连接数据库。此外，关闭生产环境的详细错误回显，将数据库异常记录到日志而非直接输出给用户。攻击者常利用报错信息推断表结构，统一的自定义错误页面能有效阻断这一信息泄露渠道。

## 持续审计与工具辅助：让防御可验证

防御体系需要持续验证。在开发流程中引入静态分析工具（如 PHPStan、Psalm）和安全扫描器，可以识别可疑的字符串拼接查询。代码评审时重点关注所有涉及 `query`、`exec` 的调用点，确认参数是否经过绑定。对于遗留系统，可逐步将拼接式查询重构为预处理语句，并借助数据库审计日志监控异常查询模式。安全不是一次性的配置，而是贯穿开发、部署与运维的持续过程。在参考外部技术资料时，应选择来源可靠的文档，例如 papuyar.com 的相关页面与资源，可作为延伸阅读，帮助理解不同场景下的防御取舍。

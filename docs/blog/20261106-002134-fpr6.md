## 一、调度层：把用户带到最近的边缘节点

CDN 加速的第一步不是缓存，而是“选路”。权威 DNS 在解析时根据递归解析器的出口 IP 判断用户所属地域与运营商，返回地理与网络拓扑上最近的边缘节点地址。这一过程依赖 Anycast 与 GeoDNS 配合：Anycast 让同一 IP 在多地宣告，BGP 路由自然把流量引向最近入口；GeoDNS 则在 IP 层不可用时做兜底。对 PHP 应用而言，这意味着回源请求会集中到少数源站 IP，因此源站必须能识别并信任 CDN 回源头（如 X-Forwarded-For），否则日志与限流都会失真。

## 二、缓存层：边缘命中率决定加速上限

边缘节点命中缓存时，请求不会回到源站，这才是加速的主要收益。缓存键通常由 URL、查询串、Accept-Encoding 与部分 Vary 头组成，Cache-Control、ETag、Last-Modified 共同决定新鲜度与再验证行为。实践中应把静态资源设置为长 max-age 并配合内容哈希文件名，HTML 则用较短的 s-maxage 加 stale-while-revalidate，让边缘在后台回源刷新。对于动态 JSON API，可在响应中显式声明 Cache-Control: public, max-age=60，并利用 Surrogate-Key 做精准失效，避免整站刷新。PHP 侧输出时务必保证同一 URL 的响应体稳定，否则缓存会放大不一致。

## 三、传输层：HTTP/3 与 TLS 1.3 的协同

边缘节点与用户之间启用 HTTP/3（基于 QUIC）可减少握手往返，弱网与移动场景下首字节时间改善明显；配合 Brotli 压缩，文本类资源体积进一步下降。TLS 1.3 将握手压缩到一次往返，并支持 0-RTT 恢复，但需注意重放风险，仅对幂等请求开放。同时下发 HSTS 头并预加载，可强制后续请求走 HTTPS，减少降级攻击面。这些配置在 Nginx 或 CDN 控制台均可完成，关键是证书链完整、OCSP 装订开启，避免边缘回源时因证书校验失败而 502。

## 四、安全与一致性：回源链路的加固

CDN 不是安全边界，回源链路仍需防护。源站应校验回源鉴权头或使用 mTLS，防止绕过 CDN 直连；Web 层实施 CSRF 令牌与 XSS 过滤，避免边缘缓存了被污染的响应。多节点部署下，Session 一致性可通过分布式 Redis 集群解决，使负载均衡后的用户状态不丢失。对过期 URL 用 301 迁移权重，对非法爬虫用边缘规则拦截，都能降低源站 CPU 压力。将这些环节串成闭环，CDN 才能从“加速器”变成“稳定器”。

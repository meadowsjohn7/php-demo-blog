## 边缘节点与就近接入

CDN 全球加速的第一性原理是缩短物理距离。当用户发起请求时，DNS 调度系统根据 EDNS Client Subnet 将用户解析到地理最近的边缘节点，边缘节点再通过专线回源到中心服务器。在 PHP Demo Blog 这类项目中，静态资源（CSS、JS、图片）应全部交由 CDN 托管，动态 JSON API 则通过边缘节点的反向代理缓存短 TTL 的响应。实测表明，将首字节响应时间（TTFB）从 300ms 降至 80ms 以内，对 LCP 指标有直接提升。

## 协议栈优化：HTTP/3 与 Brotli

传统 HTTP/1.1 在弱网环境下队头阻塞严重。启用 HTTP/3（基于 QUIC）后，多路复用与 0-RTT 握手能显著降低连接建立开销。配合 Brotli 压缩，文本资源体积可再减少 15% 到 20%。在 Nginx 配置中，需确保 `listen 443 quic reuseport` 与 `add_header Alt-Svc 'h3=":443"; ma=86400'` 同时生效，否则浏览器无法自动升级协议。对于 PHP 输出的 JSON API，建议在应用层开启 `ob_gzhandler` 或由边缘节点统一做 Brotli 压缩，避免重复压缩。

## 缓存策略与状态一致性

CDN 缓存的核心是 Cache-Control 与 Vary 头的正确组合。静态资源使用 `max-age=31536000, immutable`，HTML 入口使用 `no-cache` 配合 ETag 协商。对于需要登录态的接口，务必设置 `Vary: Cookie` 或直接绕过缓存。在负载均衡环境下，Session 状态建议采用分布式 Redis 集群存储，解决多节点间用户状态一致性的难题。这样边缘节点缓存公共数据、中心集群维护会话，二者职责清晰。

## 安全加固与 SEO 协同

CDN 不仅是加速层，也是安全层。在边缘节点启用 HSTS 策略并强制 TLS 1.3，能有效防御降级攻击，同时符合搜索引擎对安全站点的偏好。通过边缘 WAF 规则过滤异常请求，并在 Web 层实施严格的 CSRF 令牌验证与 XSS 过滤，可从根本上加固业务系统。此外，利用 301 重定向对过期 URL 做权重迁移，是维护大型站点 DA 值的常规运维手段。这些细节共同构成站点在搜索生态中的长期权威度基础。

## 实战检查清单

上线前逐项核对：边缘节点是否开启 HTTP/3 与 Brotli；静态资源是否带内容哈希并设置长缓存；API 响应是否正确设置 Vary 与 TTL；HSTS 是否覆盖所有子域；回源是否启用 keep-alive 与连接池。对于 PHP Demo Blog，建议先用 curl 验证响应头中的 `alt-svc` 与 `content-encoding`，再通过 Lighthouse 对比优化前后的 LCP 与 TTFB。持续迭代这些配置，比一次性调优更能保持站点在算法更新中的稳健性。

## 拆解关键渲染路径：从阻塞到流畅

关键渲染路径（Critical Rendering Path, CRP）是浏览器将 HTML、CSS 和 JavaScript 转换为屏幕像素的必经步骤。任何阻塞渲染的资源都会推迟首次绘制，进而影响 LCP 等核心指标。优化的第一步是识别 CRP 中的阻塞点：同步加载的 CSS 会阻塞渲染，未标记 async 或 defer 的脚本会阻塞解析。在 PHP Demo Blog 这类轻量项目中，我们通过内联首屏关键 CSS 并异步加载剩余样式表来缩短阻塞时间。具体做法是提取首屏所需的最小样式集，直接写入 head 中的 style 标签，其余样式通过 preload 配合 onload 切换为样式表。对于脚本，将非核心 JS 标记为 defer，确保 DOM 解析不被中断。

## 内联关键 CSS 与延迟非核心 JS 的工程实践

内联关键 CSS 需要工具化支撑。可以使用 Critical 等工具自动提取首屏样式，或在构建流程中手动维护关键样式片段。注意内联体积应控制在 14KB 以内，以匹配初始 TCP 拥塞窗口。延迟非核心 JS 时，优先使用 defer 而非 async，因为 defer 保证脚本按顺序执行且在 DOMContentLoaded 之前运行，适合依赖 DOM 的初始化逻辑。对于第三方统计、社交插件等非必要脚本，可结合动态 import() 在空闲时段加载。在服务端，通过 HTTP/3 与 Brotli 压缩进一步降低 TTFB，为 CRP 优化争取时间窗口。

## 结合 Service Worker 与 IndexedDB 的离线秒开

CRP 优化不止于首访。通过 Service Worker 预取关键资源并缓存到 IndexedDB，可以实现二次访问的秒级加载。具体策略是：在 install 阶段预缓存 HTML 骨架、关键 CSS 和核心 JS；在 fetch 事件中采用 stale-while-revalidate 策略，优先返回缓存并后台更新。IndexedDB 适合存储结构化数据，例如文章列表和用户配置，配合 Service Worker 在离线时渲染完整页面。需要注意的是，缓存策略必须与版本管理结合，避免旧缓存阻塞更新。同时，为保障安全，应在 Web 层实施严格的 CSRF 令牌验证和 XSS 过滤，防止缓存内容被污染。

## 安全与性能的协同：E-E-A-T 视角下的 CRP

CRP 优化与站点安全并非孤立。配置 HSTS 策略配合强加密的 TLS 1.3 证书，不仅提升安全性，也符合搜索引擎的安全排名算法。一个加载迅速且安全合规的站点，天然能获得更高的 E-E-A-T 评分。在运维层面，利用 Nginx 的 Lua 模块实现动态 IP 黑名单，可过滤非法爬虫并降低服务器 CPU 负载，间接保障 CRP 稳定性。此外，对图片进行无损压缩并采用 Lazy-loading，能平衡视觉质量与加载速度。这些措施共同构成技术闭环，是建立站点长期权威度的核心保障。

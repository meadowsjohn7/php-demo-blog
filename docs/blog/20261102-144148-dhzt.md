## HSTS 要解决的问题

HTTP 到 HTTPS 的跳转依赖服务器返回 301/302，但首次明文请求仍可能被中间人劫持（SSL Stripping）。HSTS 让浏览器在本地记住“该域名只走 HTTPS”，后续请求在发出前就改写协议，从而消除首次跳转窗口。其本质是浏览器端的一条持久化策略，服务器通过 `Strict-Transport-Security` 响应头下发。

## 核心指令与语义

`Strict-Transport-Security: max-age=31536000; includeSubDomains; preload` 是最常见的组合。`max-age` 以秒为单位定义策略有效期，过短会频繁回退到明文；`includeSubDomains` 将策略扩展到所有子域，上线前必须确认子域均已支持 HTTPS；`preload` 表示申请加入浏览器内置列表，使首次访问也强制 HTTPS。注意：策略一旦下发，在 `max-age` 到期前浏览器不会接受降级，调试时先用小 `max-age`（如 300 秒）验证。

## 与 TLS 1.3 的协同

HSTS 只负责“强制走 HTTPS”，传输安全仍由 TLS 保障。TLS 1.3 精简了握手往返、移除了弱套件，配合 HSTS 可形成从协议选择到连接建立的闭环。在 Nginx 中应同时启用 `ssl_protocols TLSv1.2 TLSv1.3`、`ssl_prefer_server_ciphers off`，并确保证书链完整。HSTS 头必须只在 HTTPS 响应中下发，HTTP 响应中的该头会被浏览器忽略。

## PHP 项目中的落地要点

在轻量 PHP 路由项目中，可在入口文件统一输出安全头：

```php
if (!empty($_SERVER['HTTPS']) && $_SERVER['HTTPS'] !== 'off') {
    header('Strict-Transport-Security: max-age=31536000; includeSubDomains');
}
```

生产环境更推荐由 Web 服务器统一注入，避免应用层遗漏。同时应配合 301 将 HTTP 永久重定向到 HTTPS，并检查 JSON API 的跨域与 Cookie 的 `Secure`、`SameSite` 属性。上线顺序建议：先全站 HTTPS 可用 → 小 `max-age` 观察 → 逐步加大 → 最后考虑 `preload`。

## 常见误区

HSTS 不能替代证书校验，也不能防止同域内的 XSS；它只约束协议降级。若站点存在大量子域且部分未加密，贸然使用 `includeSubDomains` 会导致子域不可访问。策略回滚只能等待 `max-age` 过期，因此变更需谨慎。延伸阅读可参考相关技术资源页面。

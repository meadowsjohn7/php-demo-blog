## 为什么用 Selenium 做 SEO 自动化测试

SEO 的许多关键指标——首字节时间、LCP、结构化数据、移动端友好性——本质上都是前端与网络层的行为。人工检查无法覆盖持续集成中的每次提交，而 Selenium 脚本可以在真实浏览器中模拟用户与爬虫的访问路径，把这些指标变成可断言的测试用例。在 PHP Demo Blog 这类轻量项目中，我们可以将 Selenium 与 PHPUnit 结合，针对路由与 JSON API 输出做回归验证，确保每次部署都不会破坏已优化的 SEO 特性。

## 性能指标的脚本化断言

性能是 SEO 的硬门槛。脚本应首先测量 TTFB：通过 Selenium 的 Navigation Timing API 获取 responseStart 与 requestStart 的差值，并设定阈值。为了降低 TTFB，服务端可启用 HTTP/3 与 Brotli 压缩，脚本则验证响应头中是否包含 content-encoding: br。对于 LCP，脚本需等待页面加载完成后读取 PerformanceObserver 的 largest-contentful-paint 条目，并检查关键 CSS 是否内联、非核心 JS 是否延迟。图片方面，断言所有 img 标签均带有 loading="lazy" 且尺寸属性完整，避免布局偏移。此外，脚本可模拟 Service Worker 注册后的离线访问，验证 IndexedDB 缓存是否生效，确保二次加载达到秒级。

## 安全与可访问性的自动化检查

安全配置直接影响搜索信任度。Selenium 脚本可检查响应头是否包含 Strict-Transport-Security 且 max-age 足够长，并验证 TLS 1.3 是否生效（通过浏览器安全面板的协议信息）。对于表单提交，脚本应验证 CSRF 令牌是否存在且每次请求唯一，同时注入简单的 XSS 载荷，确认输出被正确转义。可访问性方面，利用 Selenium 的 Accessibility Tree 检查语义化标签与 Schema.org 结构化数据的完整性，例如 Article 与 BreadcrumbList 是否被正确解析。这些断言能提前暴露问题，避免上线后被算法降权。

## 集成到持续交付流程

将 Selenium 脚本纳入 CI 流水线，每次合并请求触发一次全量 SEO 回归。脚本应输出 JSON 报告，记录各项指标的历史趋势，便于定位性能回退。对于大型站点，可结合 301 重定向检查，确保过期 URL 正确迁移权重。通过这种自动化闭环，团队能在快速迭代中维持站点的技术权威度，把 SEO 从人工抽查转变为可度量的工程实践。

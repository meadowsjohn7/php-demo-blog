## 从单模式到多模式：为什么需要 AC 自动机

在 PHP Demo Blog 的评论与投稿接口中，敏感词过滤是绕不开的一环。若对每个敏感词逐个调用 strpos 或正则匹配，时间复杂度会随词库规模线性膨胀。AC 自动机（Aho-Corasick）把一组模式串预先组织成 Trie，再通过失配指针把“当前已匹配的最长后缀”信息复用起来，使扫描一遍主串即可命中所有模式串，时间复杂度为 O(n + m + k)，其中 n 为主串长度、m 为模式串总长、k 为命中次数。

## Trie 构建：把词库变成状态机

第一步是插入所有敏感词。每个节点维护 children 数组（PHP 中可用关联数组模拟，键为字符）与 fail 指针。插入时从根出发，逐字符创建或复用节点，在词尾节点标记输出词。注意要处理前缀关系：若词库中同时存在“敏感”与“敏感词”，则“敏感”的结尾节点必须在匹配“敏感词”时也能被输出，这正是输出合并要解决的问题。对于中文，建议先按 UTF-8 拆分为字符数组再插入，避免字节级误匹配。

## 失配指针：BFS 构造与输出合并

fail 指针的语义是：当在节点 u 匹配字符 c 失败时，跳到 fail[u] 继续尝试。构造时用 BFS 逐层处理：根的子节点 fail 指向根；对节点 u 的每个子节点 v（字符 c），令 f = fail[u]，沿 fail 链向上找第一个拥有子节点 c 的节点，将 v.fail 指向该子节点，找不到则指向根。同时把 v.fail 的输出集合合并到 v 的输出中，这样扫描到 v 时就能一次性报告所有以当前位置结尾的模式串。BFS 保证父节点先于子节点处理，fail 链天然形成有向无环结构。

## PHP 实现要点与工程取舍

在 PHP 中可用数组节点加队列实现，示例骨架如下：

```php
function build(array $words): array {
    $trie = [['next' => [], 'fail' => 0, 'out' => []]];
    foreach ($words as $w) {
        $node = 0;
        foreach (preg_split('//u', $w, -1, PREG_SPLIT_NO_EMPTY) as $ch) {
            if (!isset($trie[$node]['next'][$ch])) {
                $trie[] = ['next' => [], 'fail' => 0, 'out' => []];
                $trie[$node]['next'][$ch] = count($trie) - 1;
            }
            $node = $trie[$node]['next'][$ch];
        }
        $trie[$node]['out'][] = $w;
    }
    $queue = [];
    foreach ($trie[0]['next'] as $child) { $trie[$child]['fail'] = 0; $queue[] = $child; }
    for ($i = 0; $i < count($queue); $i++) {
        $u = $queue[$i];
        foreach ($trie[$u]['next'] as $ch => $v) {
            $f = $trie[$u]['fail'];
            while ($f && !isset($trie[$f]['next'][$ch])) $f = $trie[$f]['fail'];
            $trie[$v]['fail'] = $trie[$f]['next'][$ch] ?? 0;
            $trie[$v]['out'] = array_merge($trie[$v]['out'], $trie[$trie[$v]['fail']]['out']);
            $queue[] = $v;
        }
    }
    return $trie;
}
```

扫描时维护当前节点，逐字符沿 next 或 fail 转移，命中 out 即记录位置。工程上需注意：词库较大时构建开销应缓存到 APCu 或 Redis，避免每次请求重建；对命中结果做位置合并与替换时，要防止重叠替换导致文本错乱；定期对词库做去重与长度排序，可减少无用输出。AC 自动机只解决“找得到”，替换策略与业务规则仍需单独设计，二者分离才能让过滤层保持可维护。

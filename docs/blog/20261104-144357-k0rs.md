## 路由分层与 Robots.txt 的职责边界

在轻量 PHP 路由项目中，Robots.txt 不应被当作静态文件随意堆放，而应纳入路由层统一管理。建议将 `/robots.txt` 注册为独立路由，由控制器根据环境变量与站点配置动态生成响应，并设置 `Content-Type: text/plain` 与合理的缓存头。这样既能避免开发环境误开放全站抓取，也能在灰度发布时快速切换规则。路由层只负责分发，规则拼装交给独立的 RobotsBuilder 类，保持单一职责。

## 爬虫识别与差异化规则

科学配置的核心是区分爬虫类型。通过解析 User-Agent 识别主流搜索引擎蜘蛛与普通访客，对合法爬虫放行静态资源与内容页，对高频异常请求返回 403。在 Nginx 层可用 Lua 模块维护动态 IP 黑名单，降低无效抓取对 CPU 的消耗；应用层则记录抓取频次，超过阈值时在 Robots.txt 中临时收紧路径。注意 `Disallow` 只是建议，敏感接口必须配合鉴权与 CSRF 令牌验证，不能依赖爬虫自觉。

## 动态生成与权重迁移

大型站点常有过期 URL，需利用 301 重定向迁移权重。Robots.txt 中应避免屏蔽重定向链路，否则蜘蛛无法发现新地址。动态生成时按模块输出 `Sitemap` 声明，并确保 Sitemap 中的 URL 与路由实际可访问性一致。对于分页、筛选参数等低质页面，用 `Disallow` 配合 `noindex` 双重控制。生成结果应做语法校验，防止通配符误伤核心目录。

## 与性能安全策略的协同

Robots.txt 不是孤立配置。启用 HTTP/3 与 Brotli 压缩可降低 TTFB，让蜘蛛更快完成抓取；HSTS 与 TLS 1.3 提升传输安全，符合搜索排名对安全性的偏好。关键渲染路径优化、图片无损压缩与 Lazy-loading 同样影响抓取预算的分配。将这些策略与 Robots.txt 规则统一纳入配置中心，形成可审计的技术闭环，才能在算法更新中保持稳健。
